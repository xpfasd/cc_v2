# 下载器页面梳理

## 结论

当前项目里没有发现独立命名或独立职责的“下载器页面” `Activity` 或 `Fragment`。

下载相关能力是嵌入在 Launcher 主界面、应用图标视图、All Apps 数据更新链路中的，而不是通过单独的下载器页面承载。

## 下载器相关 Activity

### 1. `com.android.launcher3.Launcher`

- 类型：主桌面 `Activity`
- 角色：下载相关 UI 的实际承载页
- 说明：
  - 主桌面/All Apps 的图标状态、下载进度、归档状态展示都依附在这个主界面中。
  - 项目没有单独的下载页，用户看到的“正在下载”“等待下载”“已归档”文案，本质上都显示在 Launcher 的图标和列表项上。

### 2. `com.android.launcher3.secondarydisplay.SecondaryDisplayLauncher`

- 类型：副屏 Launcher `Activity`
- 角色：副屏场景下的下载相关点击入口
- 说明：
  - 该类会在特定场景下通过 `appInfo.getMarketIntent(this)` 跳转应用市场。
  - 它不是下载器页面，只是副屏环境中的启动入口之一。

### 3. `com.android.launcher3.settings.SettingsActivity`

- 类型：设置 `Activity`
- 角色：通用设置容器
- 说明：
  - 这里承载的是 Launcher 设置页，不是下载器页。
  - 其内部只加载 `LauncherSettingsFragment`，当前默认偏好项仅包含通知点、自动添加图标、旋转等设置，没有下载器设置项。

### 4. `com.neoapps.neolauncher.preferences.PreferenceActivity`

- 类型：Neo Launcher 自定义 Compose 设置页 `Activity`
- 角色：Omega/Neo 的偏好设置入口
- 说明：
  - 这是项目自定义的设置入口。
  - 当前导航图里只有 `prefs_main`、`prefs_widgets`、`prefs_search`、`edit_icon`、`categorize_apps`、`edit_dash` 等路由，没有下载器页面路由。

## 下载器相关 Fragment

### 1. `com.android.launcher3.settings.SettingsActivity$LauncherSettingsFragment`

- 类型：`PreferenceFragmentCompat`
- 角色：默认 Launcher 设置 Fragment
- 说明：
  - 这是 `SettingsActivity` 默认加载的 Fragment。
  - 当前 `res/xml/launcher_preferences.xml` 中没有下载器相关偏好项，因此它不是下载器 Fragment。

### 2. 项目中未发现独立下载器 Fragment

- 在当前源码范围内，没有发现类似 `DownloadFragment`、`DownloaderFragment`、`DownloadsFragment` 的页面类。
- Neo/Omega 的 Compose 导航中也没有对应下载器目的地。

## 实际下载相关 UI 在哪里

虽然没有单独页面，但下载相关表现是明确存在的，主要分布如下：

### 1. 图标文案与无障碍描述

- `src/com/android/launcher3/BubbleTextView.java`
- 作用：
  - 负责把下载中的状态展示为图标文本/内容描述。
  - 会根据状态显示归档下载图标、安装中描述、下载中描述。
  - `app_downloading_title` 文案就是在这里用于内容描述的。

### 2. 下载状态模型

- `src/com/android/launcher3/pm/PackageInstallInfo.java`
- 作用：
  - 定义安装/下载状态枚举。
  - 关键状态包括：
    - `STATUS_INSTALLING`
    - `STATUS_INSTALLED_DOWNLOADING`
    - `STATUS_FAILED`

### 3. 图标状态与进度判定

- `src/com/android/launcher3/model/data/ItemInfoWithIcon.java`
- 作用：
  - 统一维护图标项的下载进度和运行时标记。
  - `FLAG_INCREMENTAL_DOWNLOAD_ACTIVE` 表示增量下载中。
  - `setProgressLevel(...)` 根据安装状态切换下载标记。
  - `isAppStartable()` 说明某些支持增量下载的应用在“已安装但仍下载资源”时可以启动。
  - `getMarketIntent(...)` 用于获取跳应用市场的 Intent。

### 4. All Apps 列表中的下载状态更新

- `src/com/android/launcher3/model/AllAppsList.java`
- 作用：
  - `updatePromiseInstallInfo(...)` 会把 `PackageInstallInfo` 更新映射到 `AppInfo`。
  - 也就是说 All Apps 里的下载进度，不是由单独页面刷新，而是由数据模型直接推动 UI 刷新。

### 5. 增量下载任务

- `src/com/android/launcher3/model/tasks/PackageIncrementalDownloadUpdatedTask.java`
- 作用：
  - 处理增量下载进度更新。
  - 同时更新：
    - All Apps 中的应用项
    - Workspace 上的应用项
  - 最终让主桌面和应用列表都感知下载进度变化。

### 6. 点击后的市场跳转

- `src/com/android/launcher3/touch/ItemClickHandler.java`
- 作用：
  - 对某些不可直接启动的快捷方式，会通过 `getMarketIntent(...)` 弹框并跳去应用市场。
  - 这里是“下载/更新入口”的交互点，但仍不是一个独立下载器页面。

## 页面归属判断

如果要从“页面”角度定义当前项目的下载器能力，可以这样理解：

- 真正承载下载状态展示的页面：`Launcher`
- 设置容器页面：`SettingsActivity`、`PreferenceActivity`
- 设置 Fragment：`LauncherSettingsFragment`
- 独立下载器页面：当前未发现
- 独立下载器 Fragment：当前未发现

## 建议的后续命名

如果后面要继续开发一个真正的下载器页，建议把它和现有“嵌入式下载状态”区分开：

- 若做完整页面：新增 `DownloaderActivity` 或 `DownloadsActivity`
- 若做嵌入式页面：新增 `DownloaderFragment` 或 Compose `DownloadPage`
- 若只保留当前模式：可描述为“Launcher 内嵌下载状态展示”，不应称作独立下载器页面
