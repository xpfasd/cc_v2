# 未完成功能

本文基于当前仓库快照整理，目标是把项目里已经明确可见的“未完成功能”集中列出来，方便后续继续开发时快速对照。

## 说明

- 当前目录实际是 `Neo Launcher` 工程快照，不是独立的“下载器”Android App 主工程。
- 本文只收录 3 类信息：
  - `README.md`、`DEVDOC.md` 里维护者明确写出的 roadmap。
  - 仓库内已有中文分析文档已经确认“尚不存在”的页面能力。
  - 源码里可直接确认的 `TODO("Not yet implemented")` 或明显功能占位点。
- 没有把所有 AOSP 上游技术性 `TODO` 都列进来，避免把普通重构备注误判成产品功能缺失。

## 二、当前确认不存在的页面能力

根据仓库中的 `下载器页面.md`，当前工程里已经明确确认：

- 没有独立命名、独立职责的“下载器页面” `Activity`
- 没有独立的“下载器页面” `Fragment`
- 下载相关状态目前是嵌入在 `Launcher` 主界面、图标状态和 All Apps 数据更新链路中的

如果后续要补齐这一块，文档里已经给出过建议方向：

- 新增 `DownloaderActivity` 或 `DownloadsActivity`
- 或新增 `DownloaderFragment` / Compose `DownloadPage`

因此，“独立下载器页面”可以视为当前项目仍未落地的一项扩展能力。

## 四、建议优先级

如果要把这份清单转成实际开发顺序，建议按下面优先级推进：

### 高优先级

- AOSP/A16 版本推进与现有特性回迁
- 备份恢复
- 分类能力（Tabs / Folders）
- 搜索引擎能力

### 中优先级

- Dock 搜索栏与主题
- 桌面旋转、尺寸命名、偏好实时应用
- 编辑应用图标
- 文件夹封面模式

### 低优先级

- Omega Widgets
- 不同抽屉布局
- 自定义搜索提供方
- 更简单的配色主题
- README 截图更新

## 五、结论

从当前仓库状态看，项目不是“没有功能”，而是处于“核心 Launcher 已可运行，但仍有一批 roadmap 功能、页面级扩展能力和局部交互实现未收尾”的阶段。

如果后续继续推进，最值得优先落地的几块是：

- 版本基线升级与旧版本特性回迁
- 分类、排序、搜索、备份恢复这类用户能直接感知的核心能力
- 弹窗控制器这类源码里已经明确标记为未实现的交互闭环
